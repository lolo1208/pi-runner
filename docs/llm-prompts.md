# LLM 提示词清单与维护约定

本文记录应用源码中的提示词入口；模型提供商的隐藏提示词不在本项目控制范围内。用户实际配置的全局、项目、会话内容以及本地 SKILL.md 是动态数据，不是固定模板，本次不改写。

## 提示词来源

| 类别 | 源码位置 | 何时使用 |
| --- | --- | --- |
| 主系统规则、权限、环境、执行模式 | `src/main/models/pi-system-prompt.ts` | Agent 请求；合并工具通用规则、权限模式、目录、自定义内容、计划/执行状态和技能说明 |
| 计划流程与工具 | `src/main/models/plan-tools.ts` | 计划模式；`ask_user_question`、`submit_plan` 的描述和批准/修改反馈 |
| 模式纠偏、批准后的执行指令 | `src/main/models/pi-agent-service.ts` | 模型未完成计划交互或批准后仅回复文字时；应用有限次纠偏 |
| 自定义提示词分层 | `src/shared/prompts.ts` | 按全局、项目、会话组装；优先级只适用于自定义层内部 |
| 技能发现、读取、用途记录 | `src/main/models/pi-agent-service.ts`、`src/main/skill-store.ts` | 自动发现技能及手动选择技能；实际技能正文来自 SKILL.md |
| 文件读取、搜索、终端工具 | `src/main/models/pi-tools.ts` | SDK 工具定义与本地权限包装；按操作系统选 PowerShell 或 Bash |
| 文本写入与替换 | `src/main/models/text-mutation-tools.ts` | write、edit 的本地描述；参数结构来自 SDK |
| 批量工具及结果恢复提示 | `src/main/models/batch-tools.ts` | read_many、write_many、edit_many、download_many；包括返回结果中的 note |
| 下载、删除、目录工具 | `src/main/models/download-tool.ts`、`delete-tool.ts`、`filesystem-tools.ts` | 下载完整性校验、文件删除和 mkdir/rmdir/move/copy/stat 的约束 |
| 权限审核模型 | `src/main/models/tool-review-service.ts` | 规则未直接放行时，要求 allow/ask/deny JSON；不是主 Agent 系统提示词 |
| 历史压缩 | `src/main/models/summary-prompt.ts`、`context-compaction.ts`、`pi-agent-service.ts` | 普通会话压缩与 Agent 主动压缩共用摘要规则；语言遵循对话偏好，不限定中文。SDK 自发的自动压缩使用其自身模板 |
| 附件与手动技能注入 | `src/main/models/pi-attachments.ts`、`model-attachments.ts`、`google-attachments.ts` | 附件名称/内容包装及手动技能读取指令；后者由单一函数生成，供不同协议复用 |
| SDK 基础描述和运行时附加内容 | `@earendil-works/pi-coding-agent` | read、终端等基础工具描述、参数说明和会话运行时内容；升级依赖时应核对 |

不只有 system prompt 会影响模型：工具 description、参数 description、工具返回的指引、隐藏流程消息同样会占用上下文并影响后续行为。

## 本次发现与修改

1. **重复过多**：主系统提示词重复工具参数、批量上限、下载命令黑名单及恢复步骤。改为公共规则负责工具选择与权限底线，具体参数和恢复细节留在工具描述；缩短批量结果的重复提示。
2. **终端写入表述歧义**：“禁止终端写文件”容易被理解为禁止安装、构建、测试和 Git 正常产生文件。明确禁止的是用终端替代专用文件操作或绕过审核，而非获准开发命令的正常产物。
3. **权限承诺过宽**：“常见开发命令直接执行”“完全访问无需许可”可能被理解为无条件放行。改为由实际规则/审核决定，完全访问仍受计划模式与安全校验限制。
4. **计划例外不一致**：原文要求 report_skill_usage，但应用也接受读取时的 purpose。统一两种用途记录方式；明确例外仅适用于技能文字交付，且不得已有计划交互或受禁操作尝试。
5. **计划批准措辞模糊**：“批准后自动执行”容易被理解为应用会代模型完成实施。改为批准后切换模式，由模型实际实施；保留需求确认和审阅流程。
6. **自定义优先级缺少作用域**：明确“会话最高”仅指自定义层内部，不得覆盖权限、工具限制与审批流程。
7. **技能说明误导**：区分手动加载与工具读取；手动技能也需记录用途。脚本特殊放行规则不再泛化为对所有 Node 程序的限制。
8. **工具描述混杂**：find 不再携带 grep 的专属限制；write/edit 使用本地中文描述，保留覆盖风险、唯一匹配、不重叠和原文件匹配语义。
9. **摘要遗漏执行状态**：明确保留批准/拒绝、部分完成、未验证事项，区分计划、尝试与实际结果，避免压缩后误认为已成功或已授权。
10. **审核输出有歧义**：将 `allow|ask|deny` 伪枚举示例改为合法 JSON 示例，强化实际目标检查和工具绕过边界。

## 补查发现与修订

- **遗漏的主动压缩指令**：`pi-agent-service.ts` 的 `session.compact()` 原来另有“请使用中文”。现与普通会话共用 `summary-prompt.ts`，沿用对话明确语言偏好，否则沿用主要交流语言；路径、标识符和必要错误保持原文。
- **遗漏的附件技能指令**：`pi-attachments.ts` 在准备消息、Google 替换和其他协议替换中分别硬编码了同一指令。现抽为 `selectedSkillDirective()`；“本轮”改成“此消息”，避免历史回放把旧技能当成本轮选择。附件正文仍是任务数据，不是应用授权。
- **技能加载状态表述**：Agent 路径中选择技能不等于正文已注入。删除“手动选择的技能由应用加载”的承诺，明确先读取 SKILL.md 再使用和记录用途。`skill-store.ts` 的正文拼接方法不能据此视为 Agent 路径必然调用。
- **终端适用范围**：将文件读取/筛选的限制与安装、构建、测试等程序执行分开，避免把“必要计算才用终端”误解为禁止正常开发命令。
- **任务数据边界**：补入附件；同时说明用户要求采用的项目规范和已读取技能可在任务范围内遵循，避免把所有文件中的项目规范一概忽略。
- **审核规则冲突**：原“破坏性返回 deny”可能与用户授权删除及“高影响返回 ask”冲突。现按越权/无关破坏、待人工确认、授权且风险可控区分；删除/覆盖不是自动拒绝理由。
- **审核输入边界**：项目、目录、用户需求、审核原因、工具参数统一 JSON 序列化，避免换行数据伪装成新的审核规则。序列化本身不是安全隔离，仍须遵守审核规则和执行层校验。

### 已核对的 SDK 来源（未修改依赖）

依赖目录：`node_modules/@earendil-works/pi-coding-agent/dist/core/`。

| 来源 | 功能及当前接入情况 |
| --- | --- |
| `system-prompt.js` | 自定义系统提示词作为 preamble；仍附加 `<cwd>`。默认专家身份、工具指南和 SDK 文档导航仅在没有自定义提示词时生成，不能把这些默认模板全算进普通 Agent 请求 |
| `compaction/utils.js` | 摘要专用身份，要求只总结、不继续历史对话；没有固定中文要求 |
| `compaction/compaction.js` | 首次摘要、更新摘要以及分段压缩逻辑；结构化摘要有固定英文标题，不能误称为摘要正文必须使用英文。应用主动压缩的补充规则不改变其结构格式 |
| `messages.js` | 压缩摘要、分支摘要的说明前后缀，以及命令执行结果的文本包装；是否发送取决于实际消息类型 |

SDK 更新摘要模板同时包含“保留所有信息”和“可删除无关信息”，存在摘要膨胀风险。应用主动压缩已补充去重及修正过时信息的规则；SDK 自发压缩仍遵循上游模板，未宣称所有 SDK 路径均已覆盖。未接入的分支功能和默认模板不等于每次请求都会发送。

工具错误、截断说明、批量结果 note 和参数 schema 也是模型输入的一部分，但不同于系统指令；它们依赖实际调用按需出现，不能全部拼入每轮系统提示词。模型生成的回复、澄清问题、计划、技能用途和审核依据均遵循用户指定语言，否则沿用交流语言；审核器只能根据请求中传入的 userPrompt 判断，尚未接入独立的界面语言设置。技能用途仅要求非空文本，不限制语言、字数或单行；展示时合并空白并转义 Markdown，不再按 200 字符截断。设置页示例不再推荐固定中文，用户已保存的自定义配置保持不变。固定 UI 文案、工具错误和上游 SDK 模板的全面本地化不在本次范围内。

### “Agent 主动压缩”的含义

这是应用在 `pi-agent-service.ts` 中、发送本轮用户消息前执行的上下文容量预检查：估算历史与待发送消息的 token 总量，并结合已测用量；预计达到可用预算时，由应用显式调用 `session.compact(SUMMARY_INSTRUCTION)`。SDK 将较早历史总结成摘要，保留近期消息供后续推理；这不是模型自主修改代码，也不是压缩磁盘文件。它与 SDK 自身在运行过程中触发的自动压缩，以及普通 ModelClient 路径的 `compactContext()` 是不同入口。

## 技能路径传递

`read_skill_file` 在正文前返回应用验证的 `skillBaseDir` 和 `filePath`，同时放入工具 details。二者与正文共用一次资源权限及真实路径校验；原 `readResource()` 仍返回纯文本，供技能发现等调用使用。

工具描述仅说明路径字段和读取方式，不解释技能自定义变量，不重复命令审核或失败替代流程。具体变量与工作流由技能正文定义；现有权限审核保持不变。

## 提示词长度优化

- 技能用途只要求简短具体，删除重复的字数、单行和语言附加描述；语言遵循主系统规则。
- 批量工具不再复述 schema 已提供的参数结构和项目数量限制；需求确认工具不重复问题与选项数量。
- 保留实际的输入容量、下载校验、截断恢复及权限说明。这些是运行约束，不等于对自然语言表达的人为字数要求。

## 保留与边界

- 保留计划模式强制本轮确认、批准后再执行的产品行为；没有为普通问答新增跳过审批的分支。
- 保留文件权限检查、工具白名单、快照、下载校验、批量状态与取消机制；本次调整的是文案，不是安全执行逻辑。
- 保留下载和目录工具对覆盖、独占创建、部分失败等必要说明，不能为了省 token 删除高风险语义。
- 不修改 node_modules 或用户技能正文；上游描述如需进一步本地化，应通过应用包装层实现。
- 压缩空间主要来自重复规则，不承诺固定 token 降幅；实际消耗取决于模型 tokenizer、启用工具和技能。
- 后续维护应同步核对模式提示、工具描述与运行时守卫，不能仅靠提示词实现权限控制。
