# 计划模式

在输入框下方切换目的模式到「计划」，然后描述任务。助手可以读取、搜索项目内容来了解现状，但计划批准前不能编辑、写入文件或运行终端命令，包括完全访问权限下。

遇到会影响方案的不确定事项，助手通过 `ask_user_question` 弹出「确认需求」窗口。一轮可有 1–3 题，每题提供多个选项及推荐项，选中「输入自己的回答」可自行填写；支持返回修改上一题的回答。界面只保留一个自定义回答入口。助手收到回答后可以继续发起新一轮问题。

需求清楚后，助手通过 `submit_plan` 提交计划。审阅窗口展示计划正文和目录。用户可以填写修改意见，点击「修改计划」继续沟通；新计划仍需批准。点击「批准计划并开始执行」后，同一请求自动切换到执行模式，按批准的计划实施。批准计划不改变原有工具权限。

批准后先结束计划轮次，再刷新执行模式提示词，并将完整批准计划交给模型开始实施。绑定项目的任务若只确认或复述计划、没有调用任何项目工具，应用会最多提醒两次继续执行；持续不执行时明确报告执行尚未开始，不将普通回复视为完成。

弹窗可收起，通过输入框上方的「回答问题」或「审阅计划」重新打开。超时秒数分别限制每次模型调用，从发起调用到收到完整响应；多轮沟通和批准后的执行各自重新计时。等待用户、执行工具以及保存文件快照不占用模型调用的超时额度。点击「停止计划」会取消当前请求，待回答或待批准的交互立即失效。

目的模式、问答内容和计划批准记录保存在本地会话中；重新打开会话可查看记录。应用退出会终止正在等待的请求，恢复后重新发送消息继续制定计划，旧弹窗不会自动执行。

实现分为主进程的交互管理、模型工具、执行限制，以及渲染进程的问答和审阅窗口。IPC 回应严格匹配请求、会话与交互编号，渲染进程不能用其他会话的回应批准计划。最终计划内容由模型生成，模型需要支持工具调用。

验收需覆盖多轮问答、自定义回答、返回修订、批准前禁止写入与终端执行、批准后实际调用工具、取消及重启后旧交互失效。当前自动测试与桌面验证记录见[验收测试](acceptance-testing.md)；完整计划流程须结合支持工具调用的模型单独验收。
