# 权限模式与自动审核

权限属于会话并永久保存。新会话在同项目已有“项目自审”或“完全访问”会话时默认选择“项目自审”，否则选择“每次询问”。不会为新会话自动开启完全访问。任务运行时不能切换模式。

| 行为 | 每次询问 | 项目自审 | 完全访问 |
| --- | --- | --- | --- |
| 项目内普通文件读取 | 直接执行 | 直接执行 | 直接执行 |
| 项目外普通文件读取 | 用户确认 | 直接执行 | 直接执行 |
| 项目或系统临时目录内修改 | 用户确认 | 直接执行；系统配置等高风险路径需人工确认 | 直接执行 |
| 项目外修改 | 用户确认 | 自动审核，不确定时用户确认 | 直接执行 |
| 终端命令 | 用户确认 | 只读与常见开发命令直接执行，其余自动审核 | 直接执行 |
| 网络 | 不单独审批 | 不单独审批 | 不单独审批 |

切换到完全访问先经主进程确认；拒绝或关闭不提升权限。保存后重启仍保留。所有模式共同禁止文件工具访问 Git 元数据、应用内部数据、敏感凭据目录、符号链接、目录联接和特殊文件；明显的毁灭性终端命令、直接文件修改命令与文件写入重定向也由公共规则拦截。

## 项目自审三层流程

1. 命令分类：只读查询以及常见包管理、构建、测试和普通 Git 操作直接执行。显式指定项目/临时目录外目标、全局安装、未知 Git 子命令、清理、硬重置、强制推送、内联求值和不明确的脚本进入审核。提权、权限及高影响系统管理操作跳过自动审核，必须人工确认。
2. 自动审核：规则仅识别单一、明确的创建、写入或修改指令及其路径；提及、否定、疑问、多个路径与移动/复制不凭路径规则自行授权。其他操作交给默认审核模型，结果必须是完整 JSON，包含 `allow`、`ask` 或 `deny` 决策。允许即继续，拒绝即停止，不确定即转交用户。
3. 用户确认：展示本次参数、工作目录和原因；批准只授权当前调用。取消、拒绝或停止任务后，待审批调用不能执行。必须人工确认的请求不能使用“重复不再提醒”。

设置 → 通用 → 默认审核模型可以指定模型或跟随默认模型。模型不可用、配置读取失败、连接失败、请求超过 30 秒、响应格式错误或使用 ChatGPT 订阅时，转交用户确认。用户提示词或操作参数超过各 2000 字符时，不向审核模型发送截断数据，转交用户查看完整调用。模型审核会把本轮需求和待审操作发送到所选模型的服务地址。

## 第一层命令覆盖

以下直接放行规则仅适用于项目自审；每次询问仍需确认终端命令。复合命令必须每一条都匹配，管道、动态展开和未知参数不能仅凭程序名称按只读放行。

| 类别 | 常见覆盖范围 |
| --- | --- |
| 文件查看与搜索 | `ls`、`cat`、`rg`、`find` 的查询形式；`bat`、`fd`、`eza`、`jq` 的已识别显示/搜索选项；哈希、大小和文件类型查询 |
| 系统与网络查询 | PowerShell 信息查询、`$PSVersionTable`、进程与磁盘查询；`ipconfig` 查询、`ip ... show`、`route print`、`ping`、DNS 查询；macOS 的 `sw_vers`、`system_profiler`、`mdls` 查询 |
| 压缩包查看 | `tar -tf/-tzf`、`unzip -l/-t/-p`、`zipinfo`、`7z l/t`；不把解压或归档创建归为只读 |
| 开发环境查询 | 独立版本/帮助参数、Node 语法检查、`python -m pip` 查询、Rust 工具链列表、npm 包信息与配置读取、Docker 与 Compose 状态查询 |
| 构建、测试与格式化 | npm/pnpm/yarn、常见编译器和构建器；Vue/Svelte 类型检查、Vite/Next/Nuxt/Astro、Biome/Ruff/Black/Mypy、Python 的常见 `-m` 开发入口、Node 测试、Swift/Zig、Bundler/Composer 等项目开发操作 |
| Windows 启动器 | 已列举开发工具的 `.cmd` / `.bat` 启动器，如 `pnpm.cmd`、`mvnw.cmd`、`gradlew.bat`；不将任意脚本都视为可信开发命令 |

查询规则与快照共用；已识别的只读查询跳过修改前快照。安装、构建、测试、格式化和项目脚本可能修改文件，仍保存执行前快照，要求项目及依赖可信。包发布、部署、账户操作、配置修改和 CMake 的 `-E` 命令入口进入后续审核；显式项目外写入目标及全局安装也进入后续审核。直接文件操作、下载落盘与写重定向仍按公共规则拦截。命令是否安全取决于参数、项目脚本和运行环境，开发工具名称本身不代表无副作用。

### 只读参数的放行条件

文件、系统、网络及 PowerShell 查询按已列举参数匹配，不再仅凭程序名放行；未知参数及不明确的组合进入后续审核。支持 `ls -la`、`rg -n` 等已知无参数短开关的组合；带值选项单独消费其参数，`--` 后的文件名也计入操作数。`uniq` 最多允许一个输入文件，第二个操作数可能是输出文件，不能认定为只读。

`rg --pre/--hostname-bin`、`sort --compress-program/-o`、PowerShell 查询的未知参数、`Get-Help -Online` 及其缩写不会按只读直接执行。`more` 等交互分页器进入审核；`bat/batcat` 只有显式设置 `--paging=never` 且其他参数均受支持时才按只读处理。显式调用 `compare.exe`、`gc.exe` 等程序不能继承同名 PowerShell 别名的只读规则；Linux/macOS 上含义不同的短别名也不沿用 PowerShell 规则。

Git 的查询子命令同样检查参数白名单。显式分页器、外部过滤器、文本转换、签名验证及未知选项不按只读放行。npm/pnpm/pip/Go 等查询若参数检查失败，不能回退到开发工具程序名放行，例如 `go env -w`、带未知日志参数的包查询、Git 查询中的未知参数均进入后续审核。

Linux/macOS 上，未加引号的通配符、反斜杠转义及不能可靠解析的引号组合可能改变实际选项，因此进入审核；需要字面量模式时使用简单单引号或双引号。Windows PowerShell 查询参数不区分大小写，但不自动接受缩写。

这里的“只读”表示已识别的查询用途和参数，不保证工具进程完全不写入缓存、不加载启动配置或不访问网络。程序替换、配置指定的钩子/过滤器/分页器、解释器启动代码及工具自身漏洞不能仅凭命令参数排除；这些仍属于本机执行环境的信任边界。

### C/C++、Visual Studio、Rust、Tauri 与 JS/TS 工具

这些工具共用专门的开发命令分类。只读查询跳过修改前快照；项目构建、测试、格式化、依赖安装、开发服务及脚本执行保留修改前快照。下表中的放行仅指项目自审，仍受公共拒绝规则及项目外目标检查限制。

| 工具 | 第一层放行 | 自动审核或人工确认 |
| --- | --- | --- |
| C/C++ 编译器 | GCC/Clang/Clang-CL/MSVC `cl` 的独立版本或帮助查询，以及普通编译、链接；Windows 的 `link/lib` | 响应文件、显式插件/外部后端/链接器覆盖、特殊工具链及高级配置入口；项目外输出 |
| vcpkg | 明确的版本、帮助、列表、搜索与依赖查询；显式设置 `--x-install-root` 的项目内安装 | 默认安装根、升级、卸载、导出及未知操作；`integrate` 修改 IDE/用户配置，必须人工确认 |
| Visual Studio/MSBuild | `vswhere`、`dumpbin` 的明确查询；MSBuild 常规 Build/Rebuild/Restore 等目标和已列举属性；`devenv /Build`、`/Rebuild` | Clean/Publish/自定义目标、未知属性/选项、外部日志器、IDE 自动化与部署；VS 安装、修复、卸载或全局配置修改必须人工确认 |
| Rust | Cargo build/check/test/run/fmt/clippy/doc、依赖更新及项目创建等明确开发入口；Rust 编译器和格式化工具；明确版本/工具链查询 | Cargo clean/publish/install/uninstall、未知别名/扩展、显式配置/注册表/工具链覆盖；Rustup 的工具链修改 |
| Tauri | 独立 CLI、`cargo tauri`、常见包管理器转发的 dev/build/init/icon，以及 Android/iOS 的 dev/build/init | 配置覆盖、插件管理、未知操作；signer/密钥操作必须人工确认 |
| Node/TS 执行器 | Node 普通 JS 脚本、test/watch、语法检查；tsx/ts-node 的明确本地脚本入口；Bun/Deno 的已列举开发子命令 | 内联求值、预加载/loader、调试入口、扩大运行权限、未知配置/交互/标准输入入口 |
| JS/TS 构建与检查 | tsc、Vue/Svelte 检查、Vite/Vitest/Jest、ESLint/Prettier/Biome、Webpack/Rollup/esbuild 等常规项目操作 | 显式清理/初始化/强制覆盖、配置或插件加载、项目外输出等 |

Cargo metadata 可能生成锁文件或下载依赖，通常按开发操作保存快照；仅已识别的 `--locked --offline --no-deps` 查询组合按只读处理。通过 `npm run` 转发的同名 Tauri 脚本仍是项目代码，包执行器还可能安装依赖，因此不把这些调用标记为纯只读查询。

Windows `/c`、`/t:Build` 等开发开关不会仅因以 `/` 开头就被误认为项目外路径；`/Fo…`、`/Fe…`、`/OUT:…`、MSBuild 输出属性、Rust `--emit=…` 等实际目标会单独提取并检查。编译器 `-g` 是调试选项，不套用包管理器全局安装规则。复杂引号、未知脚本与无法可靠解析的调用仍进入审核。

公共直接拒绝同样覆盖包装执行的文件修改与毁灭性命令，包括常见 `npx/npm exec/pnpm exec/dlx` 的包参数和筛选参数。CMake `-E` 的复制、删除、创建目录/链接等直接文件操作，以及 `dumpbin /OUT` 等诊断文本落盘，要求改用专用文件工具。普通编译产物、打包和生成代码属于开发操作，依靠执行前审核及快照处理；构建脚本、依赖钩子、配置及编译器子进程仍使用当前用户权限。

## 危险命令与第二层审核

风险规则先于第一层放行判断，覆盖 Linux、macOS 和 Windows 的常见管理命令。项目自审按以下方式路由；完全访问仍沿用已保存的授权，公共禁止规则继续生效。

| 处理方式 | 典型范围 |
| --- | --- |
| 必须人工确认，不能由审核模型直接批准 | `sudo/su/doas/pkexec`；`chmod/chown/setfacl/setcap/chattr`；`systemctl/service` 等的状态修改；`kill/pkill/killall`；重启、关机、挂载、内核模块、账户、防火墙与网络修改；`sysctl` 写入、`crontab` 修改；磁盘及分区管理；系统软件包安装、删除和升级；NULL DACL 与 Everyone 写入授权 |
| 第二层自动审核，不确定再询问 | 开发工具的清理、卸载、强制覆盖；Rust 工具链修改、Cargo 全局安装；Git `checkout/restore`、清理、重置、删除分支、强制/镜像推送及删除远程引用；发布、部署、全局配置、内联代码；curl 的远程写入、上传和跳过证书验证等参数 |
| 公共规则直接拒绝 | 已识别的毁灭性操作；直接文件修改及下载落盘；写文件重定向。Linux 直接文件命令还包括 `unlink/truncate/tee/ln/install/mktemp/fallocate/mknod`，要求改用专用文件工具 |

`npx/bunx`、包管理器的 `exec/dlx`、`uv run` 等执行器内显式调用危险命令时，不沿用开发工具名称直接放行；嵌套包装或无法确定参数含义时进入审核。简单管道、复合命令和已识别包装中的直接文件命令也参与公共拦截。未知命令默认进入第二层，命令表不是允许未知操作的依据。

审核模型必须评估实际副作用、项目外目标、远程影响与用户授权；不能仅凭“常见开发工具”批准。高影响系统操作即使出现在内联脚本或包装中，也要求模型返回 `ask`；明显越权、无关破坏或凭据外传返回 `deny`。这些判断不能替代完整脚本分析或操作系统隔离。

## 公共直接拒绝规则

直接拒绝规则先于三层审批执行，在每次询问、项目自审和完全访问中均生效。命中后不弹出批准框，也不能由审核模型放行；第三层用户确认只处理仍允许审批的操作。

| 范围 | 直接拒绝的常见命令或参数 |
| --- | --- |
| Windows 磁盘与启动破坏 | `format`、`Format-Volume`、`Clear-Disk`、`Initialize-Disk`、`Remove-Partition`，`diskpart` 脚本/交互入口；`bcdedit /delete`、`bootrec` 修复写入及 `bootsect` 启动记录覆写参数 |
| Linux 设备破坏 | `mkfs.*`、`mke2fs`、`mkswap`，`wipefs` 擦除、`blkdiscard`，`sgdisk` 清表、`parted` 分区写入，`cryptsetup` 格式化/擦除，`nvme format/sanitize`、`hdparm` 安全擦除、`badblocks -w`；识别到原始块设备目标的覆写 |
| 备份与日志销毁 | `vssadmin delete shadows`、`wbadmin delete`、`sdelete`、`cipher /w`、`wevtutil cl/clear-log`、`Clear-EventLog`、`journalctl --vacuum-*` |
| Windows 直接文件修改 | PowerShell 文件写入/删除/复制/移动命令及常见别名，`Export-Csv/Export-Clixml`、已识别的 .NET `File/Directory` 写入方法；`copy/move/ren/mklink`、`xcopy/robocopy` 实际复制、`fsutil file` 的创建与覆写操作 |
| Linux 直接文件修改 | `rm/cp/mv/mkdir/touch/ln/install` 等，`shred/dd of=...`、`rsync` 实际传输、`find -delete/-fprint/-fprintf`、`sed/perl/ruby -i`、`sort -o`、`split/csplit/sponge/patch` 的实际写入 |
| 归档与压缩写入 | `tar` 创建/更新/解包、`unzip` 解包、`7z` 增删改及解包、常见压缩器的落盘输出、PowerShell `Compress-Archive/Expand-Archive` |
| 其他公共拦截 | 文件写入重定向、已列举的下载落盘方式、已识别的经典 fork bomb |

按实际程序及参数匹配，打印文本或文档里引用命令不会仅因含有程序名就命中毁灭性命令规则。单独帮助参数，以及已识别的列表、标准输出、`--dry-run`、`/L`、`-WhatIf` 等无写入形式，不因对应的文件修改规则而拒绝；它们仍遵循当前权限模式的审核，且不能带有额外日志落盘选项。

规则会有限检查常见 `sudo/env/busybox` 包装、包管理器执行入口、`xargs`、`find -exec`，以及字面量 `sh/bash -c`、`cmd /c`、PowerShell `-Command` 的内容。最多检查三层内联文本、八层包装及 256 个命令，不读取脚本文件、不解码编码命令、不展开动态表达式。未识别的脚本仍走现有权限路由；完全访问不能因此视为具备操作系统隔离。

## 文件与终端边界

文件工具解析规范路径并逐层拒绝链接；修改前保存项目快照，审批后与实际执行前重新校验。目录删除、移动、复制先校验完整树；移动检查源与目标的写入权限，复制检查源的读取权限与目标的写入权限。目标不能覆盖已有路径。项目根目录、其父目录及系统根目录不能整棵删除、移动或复制。递归搜索和目录列表过滤内部数据与凭据目录，不跟随链接。

终端使用本机 Shell，工作目录为项目，临时变量指向系统临时目录。软件审核是执行前的风险判断，命令、项目脚本、依赖安装钩子及子进程仍具有当前用户的系统权限，不能强制保证它们只写入项目或临时目录。应仅在可信项目中直接放行开发命令。文件工具的凭据保护也不等于对终端程序的强制隔离。

项目外修改不在项目快照的回滚范围内。Electron 渲染进程仍启用 `sandbox`、`contextIsolation` 和 `webSecurity`，与工具权限审核分属不同安全边界。

## 下载文件

使用 `download({ url, path, sha256? })` 保存图片或其他二进制数据，`write` 只写 UTF-8 文本。下载属于文件修改：每次询问先批准再请求网络；项目自审在项目/系统临时目录内直接执行，项目外先自动审核；完全访问直接执行；所有模式仍检查受保护路径、链接和普通文件限制。下载修改前保存项目快照，未批准计划不开放下载工具。

下载请求为匿名 HTTP/HTTPS GET，不继承模型认证头或浏览器 Cookie，每次重定向重新检查 URL，最多 5 次。总时限 60 秒、上限 64 MiB；要求 HTTP 200、非空数据和有效长度，校验 JPEG/PNG/GIF/WebP 文件头及常见图片扩展名与响应类型，并返回 SHA-256。提供预期 `sha256` 时必须匹配；文件头校验不等于完整图片解码或恶意文件扫描。

下载写入目标旁的独占临时文件，完成后重新检查路径，再替换现有目标。失败或取消清理临时文件并保留原目标；自动创建的空父目录可能保留。下载结果只在成功保存后报告“完成”。常见终端下载落盘命令统一拦截，要求改用下载工具。

| 平台 | 拦截的常见下载方式 |
| --- | --- |
| Windows PowerShell | `Invoke-WebRequest` / `iwr`、`Invoke-RestMethod` / `irm` 的 `-OutFile`，含缩写、大小写和模块限定名称；`Start-BitsTransfer` |
| Windows 命令行 | `bitsadmin /transfer`、`/addfile`、`/addfileset`、`/resume`、`/complete`；`certutil -urlcache` |
| Windows、macOS、Linux | `curl` / `curl.exe` 的 `-o`、`-O`、`--output`、`--remote-name`、`--remote-name-all`、`--output-dir`，包括 `-sSLo`、`-LO`、`-oimage.jpg` 和长参数等号形式 |
| 安装了相应工具的系统 | `wget` / `wget2` 默认落盘及 `-O` / `--output-document`；`aria2c` 下载 |

macOS 常见的下载形式为 `curl -L -o image.jpg URL` 或 `curl -O URL`，模型应统一改为 `download({ url, path })`；`wget`、`aria2c` 是另外安装后的可选工具。curl 写响应头、Cookie、追踪日志或 libcurl 源码到文件也按写入拦截。`curl URL`、`curl -o - URL`、`curl --output=- URL` 等只输出到终端的形式不因下载落盘规则被拒绝，仍遵循当前模式的命令审核。curl 通过 `-K` / `--config` 读取配置时，配置可能隐藏输出参数，进入审核。单纯的帮助、版本和不带额外输出文件参数的 `wget --spider` 不作为下载落盘处理。

命令识别覆盖直接调用、常见参数组合、引号和命令连接，不代表能静态分析任意脚本、包装程序或动态展开。
