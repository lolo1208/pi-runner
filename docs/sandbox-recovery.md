# Windows 沙箱检查与恢复

应用启动、恢复历史会话和切换项目只读取状态，不启动隔离检测。实际终端调用先等待当前项目完成权限校验；纯聊天和专用文件工具不承担这项开销。Windows 文件隔离与开发工具能力分别检查，开发工具与联网能力延后到首次调用时检测；手动检测仍完整执行。MXC 无法启动或联网时，只要 AppContainer 文件隔离有效，受限文件命令仍可执行。界面显示开发能力限制；开发命令在 MXC 隔离与网络能力通过前不会执行，也不会转为完整本机执行。

聊天区仅在任务检查过程中显示进度，失败或能力受限时显示处理入口。空闲时的状态查询失败不显示为任务执行错误；开始任务或手动打开详情后重新查询。排查弹窗不重复展示首次使用说明、成功说明和步骤中已有的警告，失败详情及权限确认仍保留。

开发能力检查会在启用网络的 MXC 环境中验证文件读写、项目外访问、应用数据保护、链接和子进程边界。公共边界探针在同一次运行中复用；每个项目仍从实际目录验证读写与外部边界，再访问应用本次启动的本地 HTTP 服务。它不访问外部站点，也不能证明互联网或所有开发工具均可用。本地请求不使用宿主代理。

“重新配置”和“排查并修复基础问题”会按当前系统重新选择后端，不继承其他项目的选择。Windows 会把本项目旧的 `runtime-home` 改名为 `runtime-home-backup-时间戳` 后创建新目录，不删除用户项目、会话和凭据。普通“重新检测”沿用当前后端，不备份或重建已有运行配置。

每次检查使用独立的系统临时目录，不复用旧的 `pi-runner/sandbox-checks` 父目录。命令临时区和检查预检都会验证临时目录可读写，拒绝把命令临时区放入应用保护目录。失败信息包含实际路径，便于检查 `TEMP`、`TMP` 和目录权限。

AppContainer 授权前会把随机身份、项目目录身份和临时目录写入 `~/.pi-runner/command-sandbox/appcontainer-cleanup/`。正常执行结束后清理对应身份的 ACL；关机或进程中断后，在后续使用或重新配置时重试。清理不会重置项目原有 ACL，也不会跟随已重定向的目录。个别旧项目清理失败时，记录继续保留，排查页显示原因，其他项目仍可独立检查。

这些记录只能恢复本次更新后登记的身份。历史版本未登记的权限残留不能靠猜测 SID 批量清理。

每次应用重启后，上次记录都不直接授予执行资格。Windows 使用系统版本、账户、策略版本、两个运行时的清单和文件身份、临时路径、项目及关键目录身份和 ACL 生成指纹。指纹相同可在实际使用时走快速探针；本次运行内也可共享同一后端和环境的公共边界证明，但每个项目仍需实际读写及项目外访问校验。已有项目指纹变化或用户手动检测时重新完整检查。元数据未变化时复用权限指纹，避免每条命令启动 PowerShell 查询 ACL；目录内容变化时重读 ACL，但权限与身份未变不会仅因普通新增文件撤销证明。修改项目路径时，仅同一目录身份允许迁移配置；另一个目录必须重新检查。命令执行期间禁止重新配置或迁移项目权限，避免中途重置运行环境。

Windows 文件边界探针只接受明确的拒绝访问或安全异常。文件不存在、路径无效及其他普通错误不能被当作隔离已生效。原生后端也会拒绝以整个盘符或应用保护目录作为可写项目。

恢复清理会同时校验项目和临时目录的身份，目录被同名替换或重定向时保留记录并停止该项清理。旧记录没有临时目录身份且目录仍存在时，也不自动修改其 ACL。原生命令每次启动前还会检查复用的临时目录身份。

AppContainer 授权前检查硬链接，发现后明确拒绝授权。硬链接与其他路径共享文件 ACL，无法只为其中一个路径增加权限；可使用通过检查的 MXC 原生后端，或在确认文件用途后改用独立副本。该检查不自动复制或修改项目文件。

检查结果及启动失败信息保存在 `~/.pi-runner/command-sandbox/diagnostics/`，按项目路径摘要命名，每个项目保留最近一份。内容包括后端、系统版本、架构、实际临时与运行时路径、失败步骤和原始错误。开发能力首次使用时会更新进度和诊断信息；重启后重新按需检查，不直接沿用上次的开发能力状态。

修改 AppContainer C# 宿主后，需要重新生成宿主与校验清单。Windows 发行打包流程会自动执行该构建，开发环境可运行 `node scripts/build-appcontainer.cjs`。这一步只编译内置宿主，不运行沙箱测试。
