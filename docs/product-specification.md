# Pi Runner · 行动派 产品与技术规格

更新日期：2026-10-09。本文记录目标范围，实现状态以[开发路线](development-roadmap.md)和[验收记录](acceptance-testing.md)为准。

## 项目定位

面向在本地项目中执行 AI 编程任务的开发者，提供 macOS / Windows 桌面工作台。用户提出代码需求、查看工具执行过程、逐轮检查差异，并能同时恢复文件和对话上下文。目标是安全、可控、可逆的代码自动化。

## 核心能力

| 能力 | 目标行为 | 当前状态 |
| --- | --- | --- |
| 双轨时光机 | 恢复指定已完成轮次的文件与对话；支持硬恢复及分支恢复 | 每轮文件恢复已实现；分支恢复待开发 |
| 改动检查 | 每轮 A/M/D、增删行数、git-diff-view 统一/分栏对比（可展开未改动上下文） | 已实现，使用库默认增删样式 |
| 模型适配 | OpenAI、Claude、DeepSeek、Ollama、vLLM、OpenRouter、ChatGPT 订阅；自定义 Base URL、模型和参数 | 已实现，基于 pi SDK；详见[模型配置](model-configuration.md) |
| 凭证配置 | safeStorage 加密 API Key；测试连接及延迟 | 已实现；系统密钥链与桌面流程待实机验收 |
| 本地工具 | 专用文件工具、终端、权限模式、审批、三层自动审核 | 已实现；Windows 10 真机与 macOS 实机待验收 |
| 本地历史 | Session → Turn → ToolCall → Checkpoint 持久化 | 未实现；会话经 conversation-store 与 pi JSONL 保存 |
| Skill 管理 | 自定义创建、编辑及导入 Skill，查看内容、启用/停用并在任务中使用 | 已实现 |
| 计划模式（内置 Skill） | 每轮弹出选项，最后一项为自定义输入；需求明确后完整汇总，最终确认后执行 | 已实现，详见[计划模式](plan-mode.md) |

应用本地执行不意味着云模型无法看到代码；发送给远程模型的提示与代码会离开设备。本地模型也需确认 Endpoint 的实际部署位置。

## 窗口、托盘与单实例

正式运行时，关闭按钮隐藏窗口和任务栏图标，将程序收进系统托盘，保持会话、项目和后台任务。重复关闭只复用一个托盘图标。双击托盘图标或右键选择“打开”恢复并激活原窗口，恢复任务栏图标；最小化的窗口先恢复。右键选择“退出”真正退出程序，销毁托盘图标并取消后台任务。

程序启动前获取单实例锁，只有首个实例初始化服务、注册 IPC 和创建窗口；后续实例退出并通知首个实例显示界面。启动尚未完成时不提前创建窗口，退出期间不重新激活或创建窗口。Windows 系统会话结束时也清理后台任务与托盘图标。

`pnpm dev` 关闭窗口直接退出程序，包括 macOS，不创建托盘。开发环境与安装版使用独立的数据目录，但共享固定的单实例锁目录；两种启动方式之间也只能运行一个实例。

## 目标工作流

1. 创建普通对话或选择项目，配置模型、Endpoint 和凭证。
2. 提交指令；若进入计划模式，先完成下述逐轮澄清和最终确认，再进入执行。执行开始时捕获 base 快照，记录运行中的 Turn。
3. 有界 Agent 循环处理模型输出、工具调用与工具结果，支持取消和失败记录。
4. 工具停止写入后捕获 end 快照，关联轮次并展示改动。
5. 用户查看 Diff 或选择历史轮次恢复；确认影响后同步切换文件和对话。
6. 新指令基于恢复后的活动上下文与文件继续执行。

## 界面要求

输入框一次粘贴的纯文本达到 2000 个字符或 20 行时，将本次粘贴内容完整合并为一个名为“粘贴内容”的 UTF-8 文本附件（不显示扩展名），保留输入框已有文字。附件可在发送前预览、删除；发送后在对应用户消息中仍以文件卡片显示并可预览。短文本保持直接粘贴，剪贴板包含文件时优先沿用文件粘贴流程。文本附件沿用每条消息最多 8 个附件、单个附件不超过 32 MB 的限制。

左侧项目与会话历史，中间流式对话与工具事件，右侧代码/Diff。每轮嵌入 ChangedFilesList，显示状态及增删行数，二进制明确标识。设置管理模型、Endpoint、凭证和连接测试。回滚前展示影响范围与未捕获改动，区分硬恢复和分支恢复。

新建对话可选择“普通对话”，无需项目目录。左侧所有项目上方固定显示“对话”分组，可展开、收起并直接新建普通对话，不能编辑项目信息或删除分组；单条对话仍可编辑和删除。普通对话支持三种权限模式，默认每次询问，项目自审仍使用规则和 AI 审核。每条普通对话使用应用数据目录 `ordinary-workspaces/` 下的独立工作目录，同一对话跨轮次和重启复用；已有会话首次使用时迁移旧系统临时目录中的工作文件；删除对话时清理工作目录。消息历史独立持久保存，普通对话不生成项目快照，也不继承其他项目的目录或提示词。

会话项悬停或键盘聚焦时，在删除按钮之前显示编辑按钮。编辑弹窗可修改会话名称和会话提示词；保存后随会话持久化，手动名称不会被后续消息自动覆盖。会话名称不能为空，最长 200 个字符；会话提示词最长 32000 个字符。提示词从下一次发送生效，冲突时按「会话 > 项目 > 全局」优先，无冲突的指令共同生效；清空会话提示词后继续使用项目和全局提示词。

对话进行中仍可打开设置、修改项目信息和会话信息。全局、项目及会话提示词保存后从下一轮对话生效，当前轮次继续使用发送时的配置。项目目录修改先在本地保存，待当前任务结束后切换；受影响的会话队列在切换完成后继续发送。

## Skill 自定义与导入

支持用户创建和编辑 Skill，设置名称、说明与指令内容；支持从本地 `SKILL.md` 或包含它的目录导入，保留包内引用资源。导入前展示来源、内容和校验结果，名称/标识冲突时由用户选择替换或另存，不静默覆盖。管理页提供查看、编辑、启用/停用和删除，任务可显式选择 Skill，记录实际使用的版本。

内置 Skill 与用户 Skill 分开管理。计划模式作为随应用分发的内置 Skill，用户导入的同名 Skill 不得覆盖它或解除最终确认限制。导入和编辑仅保存定义，不自动执行其中的指令或脚本。首版不包含在线 Skill 市场；后续可扩展导入来源。

## 计划模式：逐轮选择，确认后执行

交互流程、持久化与门控规则见[计划模式](plan-mode.md)。规格层面的关键约束：

1. 每个交互轮次弹出选项面板，末项固定为「自定义输入」，不能仅显示普通文本问题替代选项交互；等待用户实际提交后再进入下一轮，空输入、关闭弹窗和超时不视为回答。
2. 交互完成后完整展示需求汇总（目标、背景、范围、约束、交付物、验收标准、已接受假设及执行步骤），不以摘要替代；修改或自定义补充生成新版本，必须再次完整展示并确认。
3. 只有用户明确点击「确认并执行」才进入执行；确认前不写入项目、不应用补丁、不执行 Shell。确认后范围变化时暂停相关执行并重新确认。

计划对话、答案、需求版本和确认状态需要持久化；重启后可继续澄清，但不自动视为确认或自动恢复执行。最终确认不替代执行阶段对具体危险操作的独立审批。

## 约束与范围

- 不修改用户原 `.git` 的索引、历史和配置。
- Renderer 不直接访问文件、进程、密钥或任意 IPC；主进程验证来源和输入。
- 文件工具覆盖路径越界、符号链接和平台差异；风险命令执行前审核；软件审核不提供内核级文件隔离。
- 文件系统与 SQLite 不共享原子事务；恢复需日志、恢复点和崩溃补偿。
- 文件快照不等同于磁盘级完整备份；明确排除项及元数据范围。
- 目标平台为 macOS Intel/Apple Silicon、Windows 10/11；最低系统版本须与实际 Electron 版本核对并验收。
- 云同步、多人协作、插件市场、远程项目和自动更新服务暂不纳入首版四阶段交付。
