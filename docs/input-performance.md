# 输入延迟排查与验证（2026-10-20）

## 原因与修改

输入框的草稿原来每输入一个字符都会回写顶层会话列表，触发所有已打开会话的渲染，并通过 IPC 传输全部会话数据。主进程随后校验、序列化并同步写盘。上下文统计也会重复扫描历史、工具输出和文本附件；流式文本则逐条更新 React 状态。这些操作会与输入争用处理时间。

- 草稿保持本地即时更新，向工作台同步采用 250 毫秒防抖，连续输入最多等待 1 秒。失焦、切换、提交和队列编辑边界立即同步。
- 会话和输入区稳定回调并缓存渲染；消息记录在属性未变化时跳过渲染。历史统计、草稿正文统计、草稿附件统计分别缓存。
- 可见会话每 50 毫秒合并文本增量；隐藏会话仅累计正文，切回时刷新。历史替换、重置和请求结束清理旧缓冲；审批与取消仍即时处理。
- 全量保存采用 300 毫秒防抖，最长等待 1 秒，一次仅执行一个保存请求，等待期间保留最新快照。沿用会话文件格式、主进程权限校验和临时文件原子替换。
- 正常退出时，主进程请求页面收集最新草稿，等待保存队列完成后再清理服务和退出。保存失败或 10 秒内未收到确认则保留应用并提示重试；退出确认校验窗口、主 frame 和请求标识。强制结束进程及系统强制关机不保证最后一段缓冲落盘。

## 浏览器对照结果

在本机 Chrome、Vite 开发构建中，对比 Git `863b1b0` 与修复后的工作区。使用独立模拟 API，不读取真实会话，不调用模型，不写入真实会话文件。五个会话携带相同的 100 轮长历史；每组预热后连续发送 40 次输入事件。运行中会话通过模拟文本与工具状态事件施加负载；附件组额外携带约 1 MB 文本附件。

指标从派发输入事件开始，到下一轮 `MessageChannel` 任务执行结束，包含同步事件处理与其间的 React 更新。它用于比较输入处理开销，**不是物理按键到屏幕绘制的 INP 指标**；浏览器窗口遮挡会影响帧回调，因此不以帧回调数据作验收结论。

| 场景 | 修改前 P95 | 修改后 P95 | 40 次输入的保存次数：前 → 后 |
| --- | ---: | ---: | ---: |
| 长历史、空闲 | 113.9 ms | 13.0 ms | 40 → 1 |
| 另一个会话运行 | 105.0 ms | 13.8 ms | 40 → 1 |
| 当前会话运行 | 130.9 ms | 18.7 ms | 40 → 1 |
| 四个后台会话运行 | 128.7 ms | 20.8 ms | 40 → 1 |
| 长历史与大文本附件 | 152.9 ms | 10.1 ms | 40 → 1 |

文本附件初次复测仍为 44 ms；检查后发现草稿正文变化仍会触发附件解码，拆开缓存后复测降至表中的 10.1 ms。以上是单组模拟负载结果，真实 Electron IPC、同步写盘和操作系统输入法仍应在桌面应用中复测。

## 回归与桌面验收

新增本地测试覆盖防抖和最长等待、串行保存及失败重试、退出前收集未同步草稿、后台 1000 个文本事件不渲染、切换后正文完整、重置后旧文本不回流、回调读取最新状态、输入时不重新扫描历史或解码附件。现有消息队列、中文输入法快捷键、附件、滚动、权限和窗口生命周期测试一并回归。

桌面验收使用相同的数据集和窗口大小，分别检查空闲、当前会话输出、其他会话输出、多个后台任务、长历史及附件场景。用 Performance 面板录制连续中文输入、中文输入法选词、清空、切换、发送、编辑队列，以及输入后立即从托盘退出再打开。记录输入到绘制的 P95，目标小于 50 ms，且不出现超过 200 ms 的明显停顿；确认草稿、附件、技能选择和队列编辑内容恢复正确。

最终 14 个相关测试文件、157 项测试全部通过；`pnpm build`（包含类型检查）和 `git diff --check` 通过。仓库现有规则忽略 `tests/` 与 `.tmp/`；本地回归测试与浏览器模拟夹具位于这些目录中，原始测量结果保存在 `.tmp/input-performance/results.json`。
