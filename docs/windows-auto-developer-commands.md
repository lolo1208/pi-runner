# 项目自审模式的开发命令

## 执行边界

用户确认的规则：调用项目外或全局的开发工具、测试子进程和联网无需逐次审批；读取或写入项目外普通文件仍需审批。完全访问模式沿用当前用户权限，不逐次审批命令。

项目自审模式在系统沙箱中执行。已安装工具的程序和经验证的安装资源只读，项目和独立临时区可写。npm、pnpm、Cargo 等产生的用户配置及缓存写入临时区，不开放宿主用户目录、Cargo registry/git 缓存或整个浏览器缓存目录。依赖缺失、外部共享工作区、外部配置文件仍可能产生普通程序错误，需要按具体资源处理。

## 审批修复

- `pi-tools.ts` 识别 pnpm、Node、Cargo、Git、Python 等开发调用，含带引号的绝对路径、分号组合、条件语句和 here-string 管道。模型仅因工具位于项目外或联网误设 `outsideSandbox=true` 时，仍选择受限执行路径。
- 确实需要项目外普通文件时，通过 `externalFileAccess=true` 明确请求，再走现有单次审批。专用文件工具的项目外普通文件审批保持不变；只读工具安装资产例外。
- 工具发现失败不会自动请求整条脚本获得完整本机权限。权限错误、超时或部分执行也不会重放整段迁移、构建或数据库脚本。
- 工具说明、系统提示和权限模式界面采用同一规则，不再提示开发命令联网必须申请完全访问。

## Windows 执行方式

Git 查询使用已有 AppContainer 私有项目映射，避免 Git 获取项目真实工作目录时探测受限祖先路径。支持 status、diff（包括 `--check`、`--cached`、`--stat` 和项目相对路径）及 rev-parse 查询；关闭外部 diff、textconv、fsmonitor 和可选索引锁。

开发工具使用原生 MXC 文件隔离。仅对成功解析的开发调用打开网络，子进程继承同一文件边界。简单开发命令与 Git 查询的分号组合逐项分派；带条件、管道或 here-string 的脚本保持完整执行。不会将工具调用切换成未隔离的宿主执行。

Rustup 代理使用固定的 `rustup which` 查询已安装工具链路径；实际 Cargo、rustc 和 rustdoc 在沙箱内执行，不自动安装工具链。浏览器仅开放经验证的安装资源目录；浏览器自身的兼容性失败也不会触发完整本机权限审批。

开发执行路径依赖支持 MXC 的 Windows 版本和运行时。旧版 Windows 仅支持 AppContainer 时，不能据此保证 Node 同步子进程、网络和浏览器可用；不支持时报告真实兼容性错误，不静默降级成完全访问。启动和查看历史项目只读取状态；文件隔离在实际使用终端时检查，开发工具隔离与联网能力在首次执行开发命令时检查。环境相同的公共边界探针在本次运行中复用，每个项目仍验证实际读写与外部隔离；权限、运行时或环境变化，以及手动排查，会重新完整检查。

## 验证范围

在当前 Windows 上使用真实隔离进程验证 Node、pnpm、同步测试子进程、Cargo/rustc 版本、无第三方依赖的 Cargo 离线编译测试、Git 与 pnpm 混合命令及本机 HTTP 连接。验证模型误设沙箱外执行时不触发审批，明确请求项目外文件时仍触发审批，并验证 Node 子进程不能读取或写入项目外普通文件。

当前安装的完整 Chromium 153 在 MXC 内仍返回 `0xC0000022`；Node 等待浏览器退出并检查页面响应的探针可复现。尚未定位被拒绝的具体资源，增加 Common Controls 或 WinSxS 读取没有解决，相关权限扩展已撤回。不能将“Playwright 调用免审批”等同于“浏览器兼容性已修复”，也不能用 PowerShell 提前返回的 GUI 程序退出状态证明成功。

用户列出的 Sayyo 仓库、数据库和业务测试不在此工作区，未执行它们的真实迁移或完整 Playwright 用例。命令解析测试覆盖相应调用形式，不代表其业务测试结果。macOS 仅完成相关单元测试，未在 macOS 上实测。
