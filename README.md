# Pi Runner · 行动派

Pi Runner 是面向 macOS 和 Windows 的本地桌面 AI 编程助手，基于 Electron、React 和 TypeScript 构建，让代码改动可查看、可追踪，并最终支持项目文件与对话上下文同步回滚。

当前已实现项目选择、手动与代理修改快照、git-diff-view 文件对比、模型设置、加密凭证、连接测试、流式多轮对话、文件/终端工具执行审批、Skill 管理，以及内置计划模式（逐轮澄清选项、末项自定义输入，需求确认后才执行）。SQLite 与双轨回滚（硬恢复、分支恢复）尚未实现，详见产品规格和开发路线。

## 窗口、托盘与单实例

正式运行时，点击关闭按钮会隐藏窗口和任务栏图标，并在系统托盘创建应用图标；后台任务继续运行。双击托盘图标或在右键菜单中选择“打开”会恢复并激活原窗口，重新显示任务栏图标；选择“退出”才真正退出程序，并清理托盘和后台任务。再次启动程序会打开已运行实例的界面，不创建第二个窗口或重复初始化服务。

`pnpm dev` 关闭窗口时直接退出，不创建托盘。开发环境与安装版使用独立的数据目录，但共享单实例锁；无论从哪种方式再次启动，都会打开已经运行的程序。

长会话采用虚拟列表，只渲染当前可见消息及附近内容，向上滚动可连续阅读全部历史。切换会话后保留阅读位置和展开状态；阅读历史时，新回复不会抢走滚动位置，异步卡片的高度变化会补偿阅读位置。滚轮、按键和鼠标按下不会提前清除阅读锚点，实际滚动时及时更新锚点，避免加载内容推移文字或补偿抵消用户滚动。流式文字更新复用未变化的历史消息。隐藏会话不保留消息 DOM 和尺寸监听，文件变更仅按可见范围加载，返回时按需复用缓存并重新检查已失效的文件状态。

会话侧栏和大范围代码预览同样按可见范围渲染；历史会话首次打开时才恢复，后台运行和排队继续保留。模型目录、技能、项目选择、快照、文件审查、消息队列及单轮工具记录采用分页，折叠分组不挂载内容。文件审批预览每页最多 10 项、同时最多读取 3 个文件，翻页取消尚未开始的读取；超过 1000 行的文件对比每页展示 200 行，保留原始行号、完整统计及未改动上下文。

## 工具权限

输入框下方可以为当前会话选择权限模式。同一项目已有会话中只要有“项目自审”或“完全访问”，新会话就默认使用“项目自审”；否则默认使用“每次询问”。新会话不会默认使用“完全访问”。权限按会话永久保存，完全访问在重启后也继续有效。

| 模式 | 执行规则 |
| --- | --- |
| 每次询问 | 项目内读取和搜索直接执行；每次修改文件、执行终端命令或访问项目外内容前，都会询问你是否允许。 |
| 项目自审 | 应用自动审查项目内普通文件和目录操作，无需逐项确认；终端命令通过隔离检查后在沙箱中运行。开发工具、测试子进程及联网能力可用时无需逐项审批；项目外普通文件读写仍需批准。文件隔离失败时停止终端执行。 |
| 完全访问 | 首次切换时弹窗确认；随后使用当前用户的本机权限执行文件操作、终端命令和联网，不再逐项请求批准。 |

安全命令白名单支持 `pwd`、`Get-Location`、单文件 `cat` / `Get-Content` 和目录 `ls` / `Get-ChildItem`，通过受检查的文件工具执行，不启动 Shell。Windows x64 项目自审的其他命令通过内置系统沙箱执行：只允许项目和独立临时目录读写，允许系统运行库读取，拒绝其他文件、网络及应用内部数据；Git 元数据只读，代理配置与凭据目录受保护。目录联接和子进程仍受系统边界约束。命令失败只返回错误，不自动重试或脱离沙箱。

启动应用、恢复历史会话和选择项目自审只读取状态，不启动沙箱检测，也不显示待检查或已有配置提示。首次真正执行终端命令时自动配置并校验当前项目，无需另装插件、管理员安装或手动执行配置命令。检测期间可以继续聊天和通过专用文件工具进行项目内增删改查；终端命令等待当前项目通过检测后执行，检测失败则停止，取消终端等待不会取消后台检测。Windows 的开发工具与联网能力在首次使用时单独检查；手动检测仍执行完整检查。聊天区仅在任务执行中的检查阶段显示进度，通过后自动隐藏，不额外提示成功；检查失败或能力受限时保留手动检查入口。

项目自审的配置和最近检查结果按项目保存。Windows 根据系统、运行时、隔离策略、项目身份及关键目录权限判断记录是否仍适用：重启后，环境未变的项目在首次执行命令前通过实际项目读写与外部隔离的快速探针，不能仅凭旧记录执行。公共边界检查可在同一次运行中按后端复用；其他项目仍需各自验证实际访问权限。普通命令执行前先比较元数据，目录或运行时变化时再读取权限；项目权限或环境变化、手动检测会触发完整检查。同一目录移动或重命名可识别原配置，但路径变化仍需校验。启动失败撤销该项目记录，不自动放宽权限。

Windows 与 macOS 共用 `safe-execution.json` 的记录格式和读写模块，统一处理旧记录迁移、目录身份识别、路径编辑、成功保存与失败撤销。所有后端使用相同的检测步骤名称、聊天提示和排查页面状态；各平台只提供对应的隔离执行与边界探针。读取或保存记录不会丢弃其他后端的有效项目记录，记录仍标明实际通过检测的后端，不将其他系统的证明当作当前后端的通过结果。Windows 旧记录缺少环境指纹时，首次实际使用仍须建立当前环境的隔离证明。

macOS 使用固定系统路径 `/usr/bin/sandbox-exec` 的 Seatbelt 后端和 `/bin/bash`，关闭用户启动脚本。策略默认拒绝访问，只开放项目、当前命令独立的临时 HOME，以及系统工具和常见 Homebrew 工具目录的读取；不开放用户主目录、全盘读取、应用数据或网络。项目 Git 元数据只读，配置与凭据目录禁止访问；子进程继承限制。命令结束、停止或超时后终止进程组并清理本次临时区，不转成普通终端执行。Windows 的通过记录不能替代 macOS 检测证明。系统组件缺失或策略限制时，排查页保留原因，应用不下载替代程序、不提升权限。[Seatbelt 调用方式参考](https://github.com/openai/codex/blob/main/codex-rs/sandboxing/src/seatbelt.rs)。

macOS 实机隔离验收：在 Mac 上运行 `PI_RUNNER_MACOS_SANDBOX_TEST=1 pnpm test -- tests/macos-sandbox-integration.test.ts`，覆盖真实文件和网络边界、子进程、重启与路径修改后的记录复用、超时停止。Windows 开发机只执行 macOS 的策略、进程管理和路由测试，不能据此认定 macOS 实机检测已经通过。

完整检测涵盖项目内文件增删改查、项目外文件读写、应用内部目录、目录联接、子进程和网络连接；快速探针还会在真实项目中创建并清理随机测试文件。只有配置正在运行时每 2 秒补查状态，待使用项目不轮询、不自动启动检查。单步检查最多等待 60 秒，完整准备最多 5 分钟。文件隔离失败会禁用自动终端执行；Windows 开发工具能力失败只禁用相应命令，保留文件隔离能力并显示原因。排查会恢复应用工作目录、清除失效缓存、重建执行配置并复测，展示每一步状态与失败原因；不会自动提升权限或放宽隔离边界。聊天任务执行期间禁止手动重新配置，以免更换正在使用的隔离环境。

Windows x64 接入两个后端：支持 MXC 的 Windows 11 优先使用原生隔离；Windows 10、旧版 Windows 11 或 MXC 启动不可用时使用内置 LPAC（低权限 AppContainer）宿主。兼容后端使用每条命令独立的临时身份，只对项目和独立临时目录添加受限权限，跳过联接，执行结束清理临时权限；子进程受 Job Object 约束，未授予网络或全盘读取能力。两个后端均不要求 `:root` 读取。边界测试失败不会通过切换后端绕过，也不会自动改为完全访问。Windows 10 API 兼容路径已接入，仍需 Win10 真机验收；应用始终在当前机器完整测试通过后才启用。macOS 后端尚未接入。不支持的平台显示原因并保持自动终端执行关闭。`outsideSandbox=true` 是明确申请本机权限，仍需单次批准。

内置 MXC 运行时固定为 Codex 0.159.2，仅调用本地沙箱入口，不调用模型或使用 Codex 登录；程序按固定 SHA-256 校验，发行包包含运行时及 Apache-2.0 许可证。LPAC 宿主源码和执行程序也进行 SHA-256 校验。开发机用 `pnpm sandbox:prepare <本地 Codex 0.159.2 目录>` 准备完整运行时，或用 `pnpm sandbox:build-appcontainer` 重编译兼容宿主；打包时再次校验。用户收到的是编译好的宿主，无需安装 SDK 或编译器。

Windows PowerShell 5 的部分路径操作会读取盘符或项目祖先，在严格沙箱中可能被拒绝（包括 `Remove-Item`）；此时优先改用专用文件工具，或使用项目内的标准 `System.IO` 文件 API。PowerShell 当前目录映射为 `Project:\`，原生子程序的工作目录仍为实际项目路径。依赖项目外程序、全局缓存或联网的命令也可能被拒绝；这不代表命令会自动获得本机权限。

沙箱为 Node 设置 `--preserve-symlinks --preserve-symlinks-main`，避免模块解析读取项目祖先；链接的实际目标仍由系统限制。npm 和 Corepack 缓存位于独立临时目录。

文件和目录操作使用专用工具：`mkdir` 创建目录，`write` / `edit` 写入或修改文件，`delete` 删除文件，`rmdir` 删除目录（非空目录需指定 `recursive=true`），`move` 移动或重命名，`copy` 复制，`stat` 查看信息，`ls` / `find` / `grep` / `read` 列举、查找、搜索或读取。`move` / `copy` 的目标必须不存在，不覆盖或合并已有内容。批量操作先由 `find` 列出匹配文件或目录，再逐项调用专用工具，不展开修改路径中的通配符。

文件和目录修改前保存快照，快照覆盖的文件内容可通过本轮恢复功能找回（空目录仍不属于现有快照覆盖范围）。目录删除、移动和复制会检查整个目录树；不能操作项目根目录、Git 元数据、应用内部数据、符号链接、目录联接或特殊文件。移动和复制同时检查源路径、目标路径和子项；项目外访问沿用当前权限模式的审批规则。可能修改文件的终端命令执行前同样保存快照，git status、git diff 等只读查询不保存；项目自审模式由系统沙箱限制其访问范围。

审批提示只显示操作、文件名和路径，“批准”只授权当前调用。文件改动和普通操作点击“查看详情”打开多文件对比弹窗：列出本次所有待审批文件，可折叠展开，支持统一与分栏切换，并显示每个文件的增删行数。终端命令不再复用对比弹窗：卡片仍默认只显示操作和路径，点击“查看详情”打开独立命令窗口，用代码高亮展示实际执行的命令和工作目录；只在需要脱离沙箱等扩权时显示原因，“每次询问”模式说明不再重复；沙箱恢复的原命令不同时对照显示。卡片入口和命令弹窗都提供“批准”“拒绝”，并在批准按钮前提供“重复不再提醒”勾选：勾选后本次对话不再弹出审批，后续命令直接按本次选择批准或拒绝，可在输入框上方恢复提醒。关闭弹窗不批准操作。拒绝、停止任务或真正退出程序后，待审批操作不能继续执行；关闭窗口收进托盘后仍需通过审批才能继续，等待审批不会消耗模型请求的超时时间。任务执行期间不能切换权限。项目内修改保留快照；项目外修改不在项目快照的回滚范围内。目前没有 MCP 接入。

## 快速开始

要求 Node.js 24+、pnpm 12.6.0、系统 Git。包管理器版本固定在 `package.json`，只维护 `pnpm-lock.yaml`。

```sh
pnpm install --frozen-lockfile
pnpm dev
```

也可以在项目根目录运行交互式命令菜单：

Windows 可双击 `scripts/dev-menu.bat`，或在 PowerShell 中运行：

```powershell
.\scripts\dev-menu.bat
```

macOS / Linux 在终端运行：

```sh
bash scripts/dev-menu.sh
```

菜单输入命令后按回车执行：`1` 启动开发桌面端，`2` 生成程序图标，`0` 退出。Windows 的 `a` 一次导出安装包、便携版和 ZIP 包（`pnpm dist:win:all`），`b/c/d` 分别单独导出安装包、便携版和 ZIP；macOS 的 `a` 导出安装包（`pnpm dist:mac`）。Linux 暂不支持导出发行包。命令执行结束后显示成功或失败结果，按任意键返回菜单，可继续执行其他命令。

发行内容统一复制到 `release/`，可从这里获取并分发：

| 导出命令 | 发行目录 | 内容 |
| --- | --- | --- |
| `pnpm dist:win:all` | `release/` | 一次生成 Windows 安装包、便携版和 ZIP 包 |
| `pnpm dist:win` | `release/` | Windows 安装包 `pi-runner-setup.exe` |
| `pnpm dist:win:portable` | `release/` | 单文件免安装便携版 `pi-runner-portable.exe` |
| `pnpm dist:win:zip` | `release/` | 解压即用的 Windows ZIP 包 `pi-runner-portable.zip` |
| `pnpm dist:mac` | `release/` | macOS `.dmg` 发行包 |
| `pnpm pack:dir` | `build-work/dir/` | 免安装目录版，需分发完整应用目录 |

`release/` 是最终发行目录，根目录直接存放发行文件，不创建次级目录。`build-work/` 是打包工作目录，保留目录版、更新文件、调试配置等内容。两者均不提交到 Git，也不会进入项目快照。

Windows 菜单命令 `d` 单独生成 ZIP 包，对应 `pnpm dist:win:zip`。完整解压 `pi-runner-portable.zip` 后，双击其中的 `Pi Runner.exe` 即可启动，无需安装 Node.js、pnpm 或本程序。请保留解压目录中的全部文件；ZIP 打包不需要 NSIS。

推荐使用 `pnpm dist:win:all`：只执行一次类型检查、编译、应用目录打包及运行时校验，然后并行生成 ZIP 与 LZMA2 载荷；安装包和便携版共用同一份载荷，并行生成 NSIS 外壳，外壳不再重复压缩。单独导出命令也使用同样的多线程压缩方式。Electron 语言包仅保留 `zh-CN/en-US`，应用归档排除源码映射、类型声明和开发文档，保留许可证。

Windows 发行压缩使用固定版本的 [7-Zip](https://www.7-zip.org/) `26.04`，首次按需下载并校验 SHA-256，安装包缓存于 `build-work/tools/7zip-26.04-x64.exe`；后续校验并复用工具，损坏时从已校验的安装包重新解出，可离线打包。安装包与便携版内嵌 `7z.exe`、`7z.dll` 和许可证，运行时静默解压，无需用户安装 7-Zip。7-Zip 使用 GNU LGPL 许可，相关源码见其官网；其他组件许可见随附的 `License.txt`。

Windows 发行文件使用固定名称，不添加版本号或时间后缀。若同名文件正在运行或被占用，脚本提示关闭程序后重试，已生成的包保留在 `build-work/` 中。

导出脚本固定使用 `x64` 架构。Windows 安装包和便携版使用 [negrutiu NSIS](https://github.com/negrutiu/nsis) `3.13.7507.353`，应用、外层启动程序及卸载程序均为 x64。首次运行 Windows 安装包或便携版打包命令时，自动从 GitHub 下载固定版本，验证下载文件与工具文件的 SHA-256，并缓存到 `build-work/tools/nsis-x64-3.13.7507.353/`；后续打包校验并复用缓存，损坏时重新下载。首次准备工具时，也会下载并校验官方 7-Zip `26.04`，通过 electron-builder 的解压工具解出完整 7-Zip，再解出 NSIS 文件；两个安装程序都不会执行，无需系统安装 NSIS 或 7-Zip。仓库只提交 `scripts/nsis-x64-manifest.json` 中的版本、来源和校验信息，不提交第三方工具；日常开发、macOS 打包和目录版导出不触发 NSIS 下载。工具缓存就绪、项目依赖与 Electron x64 运行时已安装、图标已生成后，可离线导出 Windows 安装包与便携版。脚本直接使用 `node_modules/electron/dist/`。Windows 安装包安装到当前用户目录，无需管理员权限；便携版临时解包后运行应用。该流程使用项目自己的 NSIS 模板，不生成 electron-updater 更新元数据，也不进行代码签名。

Windows PowerShell 若限制执行 `.ps1`，使用 `pnpm.cmd`，无需修改系统策略。

```sh
pnpm typecheck
pnpm test
pnpm build
pnpm check
```

`pnpm dev` 和 `pnpm preview` 会先执行 `pnpm electron:install`，确保 Electron 运行时已安装；已安装时直接跳过下载。当前 Electron 44 使用按需下载，`pnpm rebuild electron` 不能替代该步骤。

若 Electron 下载受阻，可先用 `pnpm install --frozen-lockfile --ignore-scripts` 安装检查和编译依赖；网络恢复后运行 `pnpm electron:install`。若 esbuild 安装脚本也被跳过且构建报错，运行 `pnpm rebuild esbuild`。

## 应用图标

将源图片命名为 `app-icon.png`，放在项目的 `resources/` 目录（即 `resources/app-icon.png`），然后手动运行：

```sh
pnpm icons:generate
```

Windows PowerShell 若限制执行 `.ps1`，使用 `pnpm.cmd icons:generate`。
支持任意宽高的静态 PNG：保持原始比例、完整保留图案，居中补透明留白后生成正方形图标，不拉伸、不裁剪，也不改动源文件。小图会放大，清晰度取决于原图。

生成文件包括 `resources/icons/` 下的 16–1024 像素 PNG、Windows `icon.ico`、macOS `icon.icns`，以及 `src/renderer/public/icons/` 下的标题栏 Logo 和 favicon。重新运行会覆盖生成文件。
首次生成或更换源图片后，需手动运行 `pnpm icons:generate`。`pnpm dev`、`pnpm build` 及打包命令直接使用已生成的图标，不会自动生成。更新正在运行的应用需要重启；安装包图标需重新运行 `pnpm dist:win` 或在 macOS 上运行 `pnpm dist:mac` 并安装新版。

## 快照体验


打开测试项目 → 创建基准快照 → 外部编辑器增删改文件 → 捕获当前改动 → 点击文件查看内联或分栏 Diff。

快照仓库与暂存区保存在用户主目录 `~/.pi-runner/projects/<项目路径哈希>/` 下，不会在项目目录创建 `.pi-runner`。移除项目会清除对应快照仓库及暂存数据，项目文件本身会保留。快照、项目列表和会话均本地持久保存，只有用户删除后才移除。

当前快照排除依赖、构建产物、元数据和部分凭证路径；拒绝符号链接、联接点及特殊文件。空目录、ACL、扩展属性和时间戳不属于覆盖范围；复制过程非原子操作，捕获时应停止外部写入。详见架构文档。

每轮文件改动提供「还原到改前」和「还原到改后」。当前项目文件内容与对应版本一致时，该入口显示「文件已同步」；还原后及切回窗口时会重新检查两侧状态，内容相同的历史版本也会同时显示同步提示。还原期间两个入口均不可重复操作。

纯聊天、文件读取与已识别的只读命令不建立任务前后快照，连续执行 `git status; git diff`、切换目录后查看状态也属于只读。第一次可能写文件的操作执行前，先保存独立恢复基线；本轮结束时比较文件内容，只有实际变化才把改前、改后两个版本加入快照历史并关联对话。同内容重写、改后又改回、仅生成被排除的缓存或日志，不新增前后对照。无法确认用途的脚本仍需准备恢复基线，不能仅根据模型描述跳过保护。手动快照和还原前的保护快照沿用原有行为。

快照采集遵循项目 `.gitignore`（含嵌套、否定规则），在复制前跳过被排除的文件和目录；不读取全局 gitignore 或 `.git/info/exclude`。没有 `.gitignore` 时仍排除依赖、常见缓存、日志与临时文件。内置排除规则优先，不能通过否定规则重新包含；项目自身 Git 已跟踪的文件也遵循这套快照规则。被排除文件不参与新快照，回滚及还原也不会覆盖或删除当前被排除的文件。每轮改动卡片、右侧栏和审查弹窗继续按当前 `.gitignore` 过滤。

暂存区采用增量同步，只复制新增或变化的文件，并移除已删除或新被排除的暂存文件。首次使用、缓存失效或恢复快照后会重建同步基线；无变化时仍需扫描未排除文件的元数据。既有快照历史保留，新增排除规则不会缩小旧仓库；需要清理时可移除项目后重新添加。

内置规则还覆盖 Visual Studio/MSVC、GCC/g++、Clang、CMake、Ninja、Autotools、Meson、vcpkg、Rust、Go、JS/TS、C#/.NET、Python、JVM、Dart/Flutter、Swift，以及 Unity、Cocos Creator、Godot 的构建产物与缓存。扩展支持 Gradle/Android、Bazel/Buck、SCons、Ruby/Rails、PHP/Laravel/Symfony、Elixir/Erlang、Haskell、OCaml、Clojure、R、Julia、Zig、Nim、D、Fortran、Xcode、Qt、LaTeX、常见站点生成器，以及 Unreal、Defold、Ren’Py，完整清单见[快照策略](docs/architecture.md#快照策略)。通用目录按项目标记限定范围；源码、资源及 `.meta`、项目配置、锁文件和预置库文件继续保留。

未知工具或自定义缓存目录可通过项目 `.gitignore` 排除；子目录含有效的标准 `CACHEDIR.TAG` 签名时，也会直接跳过整个目录。同名标记文件的签名不正确时仍保留目录。规则影响快照采集与恢复，不清理磁盘上的缓存。

应用本地运行；使用远程模型时，发送的提示和代码会传输给相应服务商。
